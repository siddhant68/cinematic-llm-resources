# Typography story system

## The viewer memory model

A long tutorial should repeatedly answer three questions:

1. Where are we?
2. What is the one idea to remember here?
3. How does it connect to the conclusion?

Use section openers for the first, memory anchors for the second, and recaps for the third.

## Role guidance

### Episode title

Use once near the opening. It should complement the spoken hook rather than delay it.

### Section open

Name a meaningful change in the argument. Use 2-7 words, one or two lines, and a consistent location or full-frame pattern.

### Hero claim

State the strongest contrarian rule, result, or takeaway. Use sparingly. A hero claim should remain readable as a still frame.

### Memory anchor

Display a compact phrase after the viewer has enough context to understand it. Keep it long enough to encode, then remove it.

### Step list

Reveal steps as the presenter reaches them. Keep prior steps visible at lower emphasis when sequence matters.

### Comparison label

Use parallel language and equal visual weight. Do not make the preferred option larger before the explanation earns that conclusion.

### Screen callout

Anchor a line, bracket, highlight, or zoom to the exact interface element. Move or remove it when the point of interest changes.

### Data point

Show source, unit, denominator, and uncertainty when relevant. Do not animate a number in a way that suggests false precision.

### Local recap

Use after dense sections. Recap 2-4 ideas, not every sentence.

### Final recap

Reassemble the major section headers in the same order they appeared. Add one final rule and leave end-screen room.

## Copy test

A graphic passes when it can be understood without audio but becomes more useful with the narration. It fails when it is merely a transcript excerpt or a slogan unrelated to the current evidence.
